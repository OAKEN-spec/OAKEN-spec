Multi-sender

One transaction, four hundred recipients.

Paste a list — one address and an amount per line — and pay them all at once. The contract holds nothing between calls: no recipient list is stored, there is no fee, and no one can pause it. A line with a zero amount is skipped; a line with a zero address stops the whole batch, because tokens sent there are gone.

Reading the list

Amounts are exact strings, never floats: 0.1 stays 0.1 rather than becoming 0.1000000000000000055. The batch is capped at 400 lines — a batch that does not fit in a block reverts after paying for everything before it, so the front end splits longer lists into two calls instead.

If it fails — self-check

  • One bad line rejects the whole batch. A zero address, a non-number or a mismatched list reverts atomically — nothing is sent. The line is marked in the form.
  • ERC-20 needs an allowance first. Choose exact or unlimited; the page shows which one the next batch needs.
  • More than 400 lines? The page splits the list into sequential calls; each one is a separate transaction and a separate gas cost.
  • A failed transaction costs gas, not tokens. The transfer that reverted did not happen.
